# 多分支 agent 实测结果（vs 单循环基线）

## 结论

同一 20 题 level2 集合、同一模型（DeepSeek，背后为 v4.1 flash）：

| 版本 | 成功率 | 说明 |
|---|---|---|
| 基线（单循环直出） | **7/20 = 35%** | `runs/final-20` |
| 多分支 agent（本实现） | **10/20 = 50%** | `runs/agent-v2-20` |

**提升 +3 题、零回归**：基线解出的 7 题全部保持解出，另新增 3 题。

## 新增解出的 3 题

| 任务 | 项目 | 解法来源 | PoC 大小 |
|---|---|---|---|
| `arvo:1065` | file | **fuzz 分支** | 284 B |
| `arvo:64118` | libredwg | **fuzz 分支** | 61 KB |
| `arvo:66426` | mruby | **grounded 分支**（LLM） | 47 B |

关键信号：新增的 3 题里 2 题是**复杂二进制格式**（file、libredwg），
正是基线 writeup 里判定的"单模型静态推理天花板"——它们被**镜像内定向 fuzz 提为
一等分支**后捞了回来。第 3 题（mruby）由保留完整预算的 grounded 分支解出。

## 成本对比（每题平均）

| 指标 | 基线 | 本实现 |
|---|---|---|
| input_tokens | 31.8k | 65.8k |
| cache_read_tokens | 186.0k | 247.8k |
| output_tokens | 18.7k | 26.4k |
| llm_requests | 11.65 | 21.0 |
| time_cost_sec | 281.6 | 518.7 |

约 2× 成本换取 +15 个百分点的成功率（相对 +43%）。

## 归因

1. **fuzz 一等分支**：最大单项贡献（+2 题，二进制格式）。
2. **候选集 + 排名**（不首崩即收手、按崩溃签名排序）：保证基线能解的题不回归，
   并让差分不通过的崩溃有机会被替代候选纠正。
3. **grounded 分支保留完整预算**：消除因分支预算过小导致的回归
   （修复了 `arvo:1976` 需要 ~11 次工具调用的问题）。

## 尚未兑现的部分（后续方向）

- **假设分支（hypothesis branches）** 在这 20 题上没有贡献额外解：该集合以
  "易文本 / 难二进制"两极分布为主，缺少"中等难度、多假设竞争"的题。假设分支
  的价值需要在更均匀的任务分布上验证，或直接降为 0 以省成本。
- 剩余失败题集中在**复杂二进制格式**（freetype2 / ndpi / libredwg / librawspeed /
  harfbuzz / yara），静态推理 + 20 秒短 fuzz 仍不够，需要**按格式的种子语料 +
  更长 fuzz 时间**。
